# RAG 回答评分器 v2 修复记录（2026-09-11）

## 结论

正式 v2 三轮报告中的低回答通过率混入了确定性字符串匹配造成的假阴性。典型答案已经表达“事务回滚、释放 Redis 预占、没有任务可恢复”，旧评分器仍因语序、短修饰词和 Markdown 反引号与 Gold 短语不完全连续而计为零分。

本次仅升级离线评分器，不修改 `rag-test-v2.json`、原始 observed、检索链路、生成提示词或模型配置。旧报告继续保留；重算结果使用 `*-rescored-v2.*` 新文件名，不能冒充原口径正式成绩。

## 修复内容

- 评分器版本升级为 `jmindops-rag-answer-deterministic@2.1.0`。
- 对 Unicode NFKC、大小写、Markdown 标记、空白、箭头和常见否定表达做归一化。
- 在同一句或同一行内校验紧邻的中文语义锚点和代码标识，允许插入“任务、字段、Redis”等短修饰内容。
- v2.1 为同一语义单元内的锚点增加最多 24 个字符的有界解释空间，可识别“切换后端不会修改向量召回、BM25 与 RRF 组成的检索主链路”这类展开表达；仍不跨句拼接。
- 不允许把不同段落中的分散词项拼成一个概念；否定概念必须保留否定锚点。
- 每题记录 `matchedConceptAliases` 与 `evidenceMatchedConceptAliases`。
- 报告记录评分器名称、版本、SHA-256 和匹配策略。

## 回归验证

脚本测试结果为 `61 passed, 12 skipped`。其中新增测试覆盖 Markdown/短修饰词、复合断言、跨语义单元误拼接、否定语义保护，以及开发集不得退回旧关键词标签或缺失主证据路径。

当前 `rag-gold-v1.json` 的 SHA-256 为 `c0dd73387fac2be80d1b8008771730e7ef3601eb75f5affdfe0bbe355f6b72c4`，而 2026-09-09 observed 绑定的是旧 Hash `f2cfa1e06c311e8c6045fe1c81815db9a7d8d1f0eebf556ff6448fe60fe22615`。评分器按契约拒绝跨版本重算，因此没有绕过 Hash 校验复用该开发集结果。当前开发集使用 `--allow-draft` 的结构与证据校验通过，共 35 题。

## 开发集评分契约迁移

`rag-gold-v1.json` 的 30 道可回答题已从 `expectedKeywords` 全部迁移为 80 个原子 `expectedConcepts`，并为每题增加 `sourcePaths`，由校验器确认每个概念都能在第一主证据中找到依据。默认完整性阈值调整为 `1.0`，因此每个独立概念都必须被回答覆盖；同义表达放在同一个 `anyOf` 中，不再把 `heartbeat/心跳`、`单行化/单行文本` 一类同义词重复计分。

原 `rag-answer-024` 要求回答 HNSW 与 IVFFlat，但三份锁定主语料均未提供这些信息。该题已替换为语料明确支持的“文档更新时如何保证新旧索引原子可见”，避免把模型外部常识冒充知识库答案。只询问错误码或状态标记的题目也删除了与问题无关的附加要点，例如同键异参题只要求 `409`，未部署重排题要求 `NOT_CONFIGURED` 及其“未测试”语义。

这次迁移没有把开发集伪装成人工终审结果：`annotationStatus` 仍为 `DRAFT`、`frozen=false`。旧 observed 与新题集 Hash 不匹配，必须重新实跑；项目所有者完成逐题复核前仍需显式使用 `--allow-draft`/`-AllowDraft`。

## 后续边界

v2 已被用于失败分析。后续可以把它作为严格回归集；生成提示词、上下文拼装或检索参数若根据 v2 结果调整，最终对外成绩应使用未曝光的新题集。评分器 v2 仍是确定性语义代理，不替代固定 Judge、RAGAS Faithfulness 或人工事实核验。
