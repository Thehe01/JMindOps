# 07 - 第 6 步：事件驱动架构与 SSE 流式推流

#JMindOps #SSE #SseEmitter #ConcurrentHashMap #EventDriven #SingleFlight

> [!NOTE] 
> 目标：实现大模型打字机流式输出。基于 Spring Event 实现推理与推流持久化解耦，管理高并发长连接管道，并设计 Single-Flight 会话防并发机制。

---

## 1. 为什么选择 SSE 而不是 WebSocket？

- **单向流传输**：AI 对话是“客户端发请求，服务端单向喷流”，单向完全够用；
- **标准 HTTP 协议**：天然走现有 Nginx、反代和网关，直接支持 `Authorization: Bearer <JWT>` 头；
- **自动断线重连**：浏览器原生协议层支持。

---

## 2. 概念解析：SseEmitter vs ConcurrentHashMap

| 核心组件 | 现实生活比喻 | 底层技术实现 | 核心职责 |
| :--- | :--- | :--- | :--- |
| **`SseEmitter`** | **自来水管** | Spring 封装的异步长连接管道对象 | Controller 返回后不关闭 HTTP 连接，随时通过 `send()` 推送字块 |
| **`ConcurrentHashMap`** | **防冲突通讯录** | Java `CAS + Synchronized` 分段锁哈希表 | 多线程高并发下，安全管理所有 Session 的水管集合，杜绝并发报错 |

## 3. SSE 长连接服务实现 (`SseServiceImpl.java`)

```java
@Service
public class SseServiceImpl implements SseService {
    // 线程安全管理：sessionId -> SseEmitter 集合
    private final ConcurrentMap<String, Set<SseEmitter>> clients = new ConcurrentHashMap<>();
    private final ObjectMapper objectMapper;

    @Override
    public SseEmitter connect(String chatSessionId) {
        SseEmitter emitter = new SseEmitter(30 * 60 * 1000L); // 30 分钟超时

        clients.compute(chatSessionId, (key, existing) -> {
            Set<SseEmitter> emitters = existing == null ? ConcurrentHashMap.newKeySet() : existing;
            emitters.add(emitter);
            return emitters;
        });

        // 监听断开钩子，自动清理通讯录
        emitter.onCompletion(() -> removeClient(chatSessionId, emitter));
        emitter.onTimeout(() -> removeClient(chatSessionId, emitter));
        emitter.onError(err -> removeClient(chatSessionId, emitter));
        return emitter;
    }

    @Override
    public void send(String chatSessionId, SseMessage message) {
        Set<SseEmitter> emitters = clients.get(chatSessionId);
        if (emitters != null) {
            String json = objectMapper.writeValueAsString(message);
            for (SseEmitter emitter : emitters) {
                emitter.send(SseEmitter.event().name("message").data(json));
            }
        }
    }
}
```

## 4. Single-Flight 会话防并发协调器 (`ChatGenerationCoordinator.java`)

### ❓ 为什么需要 Single-Flight？
防止用户狂点发送按钮导致同一个 Session 同时跑多个 Agent 实例，引发记忆乱序和 SSE 屏幕打字混乱。

```java
@Component
public class ChatGenerationCoordinator {
    private final ConcurrentMap<String, String> generationsBySession = new ConcurrentHashMap<>();

    // 1. 消息落库前预占位（已有任务直接抛 409 拒绝）
    public String reserve(String sessionId) {
        String generationId = UUID.randomUUID().toString();
        if (generationsBySession.putIfAbsent(sessionId, "reserved:" + generationId) != null) {
            throw new BizException(409, "该会话已有生成任务，请等待完成后再发送");
        }
        return generationId;
    }

    // 2. 异步监听器认领执行
    public boolean claim(String sessionId, String generationId) {
        return generationsBySession.replace(sessionId, "reserved:" + generationId, "running:" + generationId);
    }

    // 3. 无论成功或异常，finally 中释放
    public void release(String sessionId, String generationId) {
        generationsBySession.remove(sessionId, "running:" + generationId);
        generationsBySession.remove(sessionId, "reserved:" + generationId);
    }
}
```
